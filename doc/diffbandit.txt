OVERVIEW                                            *diffbandit-overview*

DiffBandit is a Neovim diff viewer with independent source panes, docked line
number panes, compact connector geometry, Git-aware navigation, hunk actions,
a commit panel, binary hex diffs, 3-way merge conflict resolution, and
read-only folder comparison, and theme-adaptive highlights.

The layout is designed around source buffers that keep natural scrolling while
the gutter explains how changed regions relate. Line numbers stay attached to
their corresponding document, and the connector pane draws routes between
additions, deletions, changes, mixed hunks, and scroll-clipped regions.

Core features:

- Three-part diff layout with visual connector gutter.
- Independent scrolling for left and right content.
- Git queue navigation with |diffbandit-]f| and |diffbandit-[f|.
- Hunk staging, unstaging, apply/discard actions, and undo.
- Optional commit panel with file staging and commit message entry.
- Merge conflict group with a local/result/remote resolver.
- Recursive folder comparison using external digest commands.
- One-column overview gutters at the outer document edges.
- Read-only binary hex comparison view.
- Theme-friendly colors derived from the active colorscheme.

INSTALLATION                                      *diffbandit-installation*

With lazy.nvim:
>
  {
    "CoreyKaylor/diffbandit.nvim",
    cmd = {
        "DiffBandit",
        "DiffBanditBuffers",
        "DiffBanditFolderDiff",
        "DiffBanditGit",
        "DiffBanditGitCurrent",
        "DiffBanditCommitPanel",
        "DiffBanditGitMenu",
        "DiffBanditGitLog",
        "DiffBanditGitCommit",
        "DiffBanditGitCompare",
        "DiffBanditGitCheckout",
        "DiffBanditMerge",
    },
    opts = {},
  }
<

Requirements:

- Neovim 0.10 or newer.
- Git for Git diff workflows and hunk actions.
- tmux only for the optional real-terminal smoke test.
- Nerd Fonts are optional.
- Image (Kitty graphics) connectors: Neovim 0.12+, 'termguicolors', and a
  terminal with Kitty graphics + Unicode placeholders (Ghostty, Kitty, ...).
  Inside tmux 3.3+ they also need `set -g allow-passthrough on` and the RGB
  terminal feature; see the README section "tmux" for setup, limitations and
  troubleshooting. `ui.connector_renderer = "cells"` disables them.

COMMANDS                                            *diffbandit-commands*

                                                        *:DiffBandit*
:DiffBandit {left} {right}
        Open a DiffBandit view comparing two files.

                                                 *:DiffBanditBuffers*
:DiffBanditBuffers {left-bufnr} {right-bufnr}
        Open a DiffBandit view comparing two loaded buffers.

                                             *:DiffBanditFolderDiff*
:DiffBanditFolderDiff {left-folder} {right-folder}
        Open a read-only recursive folder comparison.

                                                     *:DiffBanditGit*
:DiffBanditGit [flags] [--] [pathspec...]
        Open a Git diff queue for the current repository. By default this uses
        all changes, including staged, unstaged, and untracked files.

                                              *:DiffBanditGitCurrent*
:DiffBanditGitCurrent [flags] [path]
        Open a Git diff for the current buffer, or for the supplied path.

                                             *:DiffBanditCommitPanel*
:DiffBanditCommitPanel [flags] [--] [pathspec...]
        Toggle the Git commit panel. When used outside an active Git diff
        session, it opens as a standalone side panel.

                                                *:DiffBanditGitMenu*
:DiffBanditGitMenu
        Open a Git workflow action menu.

                                                 *:DiffBanditGitLog*
:DiffBanditGitLog [--all] [--max-count N] [--] [pathspec...]
        Open a read-only Git log browser. Press <CR> on a commit to review its
        changed files in a DiffBandit queue. In that review, `]r` steps to the
        next (older) commit in the log and `[r` to the previous (newer) one,
        staying on the same file when the commit touches it; with a pathspec
        this walks one file's history. Keys: `git.log_keys` in |diffbandit-configuration|.

        Each row shows the hash, age, author, lines added and removed, refs,
        and subject; the counts fill in once git has measured them. A detail
        pane beside the list shows the commit under the cursor: refs, author
        and committer, the full message, and its files with line counts.
        `p` toggles the pane, `R` refreshes, and <CR> on a file in the pane
        reviews the commit starting at that file. Options: `git.log`.

                                              *:DiffBanditGitCommit*
:DiffBanditGitCommit {rev}
        Open a read-only review of the files changed by {rev}.

                                             *:DiffBanditGitCompare*
:DiffBanditGitCompare [base] [target] [--direct]
        Open a read-only comparison between two refs. Without refs, branch
        pickers are shown.

                                            *:DiffBanditGitCheckout*
:DiffBanditGitCheckout [branch]
        Switch to [branch], or prompt for one. The command refuses dirty
        worktrees and in-progress Git operations by default.

                                                   *:DiffBanditMerge*
:DiffBanditMerge [path]
        Open a three-pane resolver for an unmerged Git conflict. If [path] is
        omitted, the current buffer path is used.

                                                   *:DiffBanditClose*
:DiffBanditClose
        Close the DiffBandit view in the current tab: a diff, merge, or folder
        session together with its tab page, or a standalone commit panel.
        Equivalent to pressing `q`.

                                                  *:DiffBanditLaunch*
:DiffBanditLaunch
        Entry point for the `bin/diffbandit` launcher; see
        |diffbandit-launcher|. It reads its arguments from the environment
        the script sets and refuses to run otherwise.

                                           *:DiffBanditToggleStageHunk*
:DiffBanditToggleStageHunk
        Toggle the staged state of the active Git hunk.

                                                  *:DiffBanditStageHunk*
:DiffBanditStageHunk
        Stage the active Git hunk.

                                                *:DiffBanditUnstageHunk*
:DiffBanditUnstageHunk
        Unstage the active Git hunk.

                                                *:DiffBanditDiscardHunk*
:DiffBanditDiscardHunk
        Discard the active Git hunk from the worktree.

                                              *:DiffBanditApplyLeftHunk*
:DiffBanditApplyLeftHunk
        Apply the left side of the active hunk to the right target.

                                             *:DiffBanditApplyRightHunk*
:DiffBanditApplyRightHunk
        Apply the right side of the active hunk to the left target.

                                                        *:DiffBanditUndo*
:DiffBanditUndo
        Undo the last DiffBandit action for the current file.

DEFAULT MAPPINGS                                  *diffbandit-mappings*

Mappings are buffer-local inside DiffBandit buffers. Every DiffBandit view
answers |diffbandit-g?| with the keys of the window you are in, and each
mapping carries a "DiffBandit: ..." description, so `:map`, which-key, and
keymap pickers explain them too.

                                                       *diffbandit-g?*
  g?            Show the keys of the current window in a floating window,
                grouped by purpose, with a legend for the diff header and the
                panel's staged symbols. The list is read from the live
                mappings, so remapped and disabled keys are shown as they are.
                q, <Esc>, or g? closes it. Headers show a "g? help" hint.
                Set by `navigation.help_key`; false disables the key and the
                hints.

Diff view mappings:

                                                        *diffbandit-]c*
  ]c            Jump to the next hunk.

                                                        *diffbandit-[c*
  [c            Jump to the previous hunk.

                                                        *diffbandit-]f*
  ]f            Jump to the next changed file in a Git queue.

                                                        *diffbandit-[f*
  [f            Jump to the previous changed file in a Git queue.

                                                        *diffbandit-]r*
  ]r            In a commit review opened from the log, open the next
                (older) commit in place, staying on the same file.

                                                        *diffbandit-[r*
  [r            In a commit review opened from the log, open the previous
                (newer) commit in place.

                                                        *diffbandit-[d*
  [d            Align both panes to the top of their documents.

                                                        *diffbandit-]d*
  ]d            Align both panes to the bottom of their documents.

                                                        *diffbandit-]s*
  ]s            Snap the other pane to the line facing the cursor line,
                preserving the cursor's screen offset.

                                                        *diffbandit-C*
  C             Open or focus the commit panel for the current Git file.

                                                  *diffbandit-<Space>*
  <Space>       Toggle staged state for the active Git hunk.

                                                       *diffbandit->>*
  >>            Apply the left side to the right target.

                                                       *diffbandit-<<*
  <<            Apply the right side to the left target.

                                                        *diffbandit-u*
  u             Undo the last DiffBandit hunk action for the current file.

                                                      *diffbandit-gzp*
  gzp           Show or hide the commit panel for a Git diff.

                                                        *diffbandit-q*
  q             Close the diff session. Set by `navigation.close_key`;
                false disables it.

At a file boundary, |diffbandit-]c| and |diffbandit-[c| first notify that the
next press will move to the next or previous file. This keeps file navigation
deliberate while reviewing a Git queue.

FOLDER DIFF                                      *diffbandit-folder-diff*

Open a read-only recursive folder comparison with:
>
  :DiffBanditFolderDiff path/to/left path/to/right
<

DiffBandit aligns matching relative paths from both folder roots and compares
same-size files with an external digest command such as md5sum, md5, or
shasum. Folder comparison does not read file contents into Lua; the ordinary
text or hex diff is loaded only after opening a file row.

Folder diff mappings:

  <CR> or o      Open the selected file pair, or toggle a directory.
  ]c / [c        Jump to the next or previous visible difference.
  <Space> / za   Expand or collapse the selected directory.
  zR / zM        Expand or collapse all directories.
  s              Change the status filter.
  R              Refresh the folder comparison.
  q              Close the folder diff.
  <<             Editable folders only (`diffbandit edit`): make the right
                 file or directory match the left. A right-only entry is
                 removed, a left-only one restored, a changed one reset.
                 Under `jj split` this moves the entry out of the first
                 commit.
  u              Editable folders only: undo the last <<.

Opening a file row creates a child DiffBandit file diff. Pressing q in that
child diff returns to the original folder comparison with the selected row
restored.

GIT DIFFS                                                *diffbandit-git*

Git flags supported by |:DiffBanditGit|, |:DiffBanditGitCurrent|, and
|:DiffBanditCommitPanel|:

  --staged        Show staged changes only.
  --cached        Alias for --staged.
  --all           Show staged and unstaged changes.
  --current       Scope the Git queue to the current file.
  --base {rev}    Compare all changes against {rev}.
  --rev {spec}    Compare revisions. Supports A..B or A B forms; A...B
                  compares B against the merge base of A and B.
  --no-untracked  Exclude untracked files.
  --              Treat remaining arguments as pathspecs.

Examples:
>
  :DiffBanditGit
  :DiffBanditGit --staged
  :DiffBanditGit --base main
  :DiffBanditGit --rev main..HEAD
  :DiffBanditGit -- -- lua/diffbandit
  :DiffBanditGitCurrent
<

Git workflow helpers:
>
  :DiffBanditGitMenu
  :DiffBanditGitLog --all --max-count 50
  :DiffBanditGitCommit HEAD
  :DiffBanditGitCompare main feature
  :DiffBanditGitCompare main feature --direct
  :DiffBanditGitCheckout feature
<

Commit and branch review views are read-only Git queues. They reuse normal
file and hunk navigation, but staging, discard, apply, and commit actions are
disabled. Branch comparison defaults to merge-base(base, target)..target; use
--direct for an exact ref-to-ref comparison.

Binary files render as read-only hex diffs by default. Disable that behavior
with:
>
  require("diffbandit").setup({
    ui = {
      hex = {
        enabled = false,
      },
    },
  })
<

LAUNCHER                                            *diffbandit-launcher*

`bin/diffbandit` opens DiffBandit for the repository in the current
directory: the panel lists every changed file and selecting one opens its
diff. `q` quits nvim, as does closing the last DiffBandit view. Link the
script onto PATH as `diffbandit`, and as `git-diffbandit` for
`git diffbandit`.

Arguments follow `git diff`:
>sh
  diffbandit                    # working tree changes, with the panel
  diffbandit --cached           # staged changes
  diffbandit main               # working tree compared with main
  diffbandit main feature       # read-only review, also main..feature
  diffbandit main...feature     # review against the merge base
  diffbandit show HEAD          # review a single commit
  diffbandit main -- lua/       # cwd-relative pathspecs
<
Subcommands:
>sh
  diffbandit compare [<base>]   # branch work, committed or not, against
                                # its merge base with <base> (default:
                                # origin/HEAD, else main or master)
  diffbandit compare --direct <base>  # against <base> itself
  diffbandit compare --unpushed # against the upstream
  diffbandit compare <a> <b>    # read-only review, same as <a>...<b>
  diffbandit log [--all] [-n <count>] [<rev>] [-- <path>...]
  diffbandit stash [<n>]        # review stash@{<n>}
<
`compare` keeps the commit panel and the editable working tree; hunk
staging stages only a hunk's pending lines, never committed ones. The log
loads the latest 1000 commits unless `-n` is given, and closing a review
opened from it returns to the log. A subcommand wins over a branch or path
of the same name: `diffbandit -- log` means the path.

The launcher uses your normal nvim config and runs |:DiffBanditLaunch|, so a
lazy-loaded plugin should list that command among its load triggers.
`DIFFBANDIT_NVIM_APPNAME` selects a dedicated config (`NVIM_APPNAME`) and
`DIFFBANDIT_NVIM` the nvim executable.

External tool mode works outside any repository:
>sh
  diffbandit diff LEFT RIGHT     # read-only folder or file diff
  diffbandit edit LEFT RIGHT     # edit the right folder/file in place
  diffbandit merge BASE LEFT RIGHT OUTPUT [--path P]  # :w resolves
<
`merge` exits non-zero unless the result was saved with `:w`, so jj and
`git mergetool` (with trustExitCode) keep the conflict. Git setup:
>sh
  git config --global mergetool.diffbandit.cmd \
    'diffbandit merge "$BASE" "$LOCAL" "$REMOTE" "$MERGED" --path "$MERGED"'
  git config --global mergetool.diffbandit.trustExitCode true
  git config --global difftool.diffbandit.cmd 'diffbandit diff "$LOCAL" "$REMOTE"'
<
See |diffbandit-jj| for the jj configuration.

COMMIT PANEL                                  *diffbandit-commit-panel*

Open the panel with |:DiffBanditCommitPanel| or press |diffbandit-C| from a
Git diff opened by |:DiffBanditGit|.

Panel mappings:

  j / k         Move through changed files and preview the selected file.
  <CR>          Focus the diff for the selected file.
  ]c / [c       Navigate hunks in the selected file preview.
  <Space>       Toggle staged state for the selected file.
  a             Open file actions for the selected file.
  cc            Focus the commit message window.
  R             Refresh the panel.
  gzp           Hide the panel, keeping the diff open.
  q             Close the whole view: the diff or merge resolver with its
                tab page, or the standalone panel. Same as |:DiffBanditClose|.

Closing a view keeps an unfinished commit message: it is saved for the
repository and restored by the next commit panel opened there. Committing
clears it. Moving the panel selection between a merge conflict and a changed
file swaps the view in place, in the same tab page.

Commit message window mappings:

  <Space>       Toggle amend mode.
  :w            Commit staged changes using the buffer contents as the message.

Set `git.panel.keys.toggle_amend` to a key other than <Space> and the file
stage key, and it works in the file list too.

The panel validates empty commit messages and missing staged changes before
committing, and rejects commits while merge conflicts remain unresolved. In
amend mode, the panel compares against the previous commit so the file state
reflects what the amended commit would contain.

File actions include staging, unstaging, discarding unstaged tracked changes,
restoring deleted tracked files, deleting untracked files, and adding useful
.gitignore patterns for untracked files.

==============================================================================
MERGE CONFLICTS                                          *diffbandit-merge*

Conflict files appear in a "Merge Conflicts" group above normal changes in the
commit panel. Selecting a conflict opens a three-pane resolver:

  left    Local/current Git stage (ours), read-only.
  center  Editable result, initialized from the base stage.
  right   Remote/incoming Git stage (theirs), read-only.

Merge mappings:

  ]c / [c       Move to the next or previous conflict.
  >>            Accept local/current into the result.
  <<            Accept remote/incoming into the result.
  gb            Accept both sides, local then remote.
  gA            Apply non-conflicting changes from both sides.
  ]s            Snap the other two panes to the line facing the cursor line,
                preserving the cursor's screen offset.
  gzp           Toggle the commit panel.
  gzh           Toggle the left (local) pane.
  gzl           Toggle the right (remote) pane.
  gza           Show all hidden panes and the panel.
  :w            Write the result and mark the file resolved with git add.

Hiding a pane or the panel gives its width to the remaining panes, for
focusing on the editable result on narrow screens. The center result pane is
always visible.

DiffBandit warns when conflict stages have mixed line endings, but it does not
normalize line endings automatically.

==============================================================================
HUNK ACTIONS                                    *diffbandit-hunk-actions*

Git hunk actions operate on the active hunk in Git diff sessions:

  <Space>       Stage an unstaged hunk or unstage a staged hunk in all mode.
  >>            Apply the left side of the hunk to the right target.
  <<            Apply the right side of the hunk to the left target.
  u             Undo DiffBandit apply/stage actions in reverse order.

Remap these with `actions.keys`, or set a key to false to leave it unmapped.

Staged hunks show an indicator next to the right-side line numbers. Defaults
use plain Unicode squares so patched fonts are optional.

LUA API                                              *diffbandit-lua-api*

>
  local diffbandit = require("diffbandit")

  diffbandit.setup({})
  diffbandit.files("left.txt", "right.txt")
  diffbandit.buffers(left_bufnr, right_bufnr)
  diffbandit.folder_diff("left-dir", "right-dir")
  diffbandit.git({ mode = "all" })
  diffbandit.git_file(nil, { mode = "all" })
  diffbandit.git_menu({})
  diffbandit.git_log({ all = true, max_count = 50 })
  diffbandit.git_commit("HEAD")
  diffbandit.git_panel({})
  diffbandit.launch({ "main...HEAD" })
  diffbandit.git_compare("main", "feature")
  diffbandit.git_compare_branches({})
  diffbandit.git_checkout("feature")
  diffbandit.merge("path/to/conflicted-file")
  diffbandit.merge_files({ base = "B", left = "L", right = "R", output = "O" })
  diffbandit.commit_panel({})

  diffbandit.toggle_stage_hunk()
  diffbandit.stage_hunk()
  diffbandit.unstage_hunk()
  diffbandit.discard_hunk()
  diffbandit.apply_left_hunk()
  diffbandit.apply_right_hunk()
  diffbandit.undo()
<

TESTING                                              *diffbandit-testing*

Run everything (unit specs and integration tests, in parallel):
>
  nvim -l tests/run_all.lua
<

The first run fetches mini.test into `deps/` (`tests/deps.sh`).
`DIFFBANDIT_TESTS=scroll,git` runs only the matching jobs;
`DIFFBANDIT_JOBS=N` sets the worker count.

The integration tests drive headless child Neovim instances and read the
drawn screen cell by cell, including colors, so they verify connector
geometry, backgrounds, underline spans, Git actions, commit panel behavior,
binary diffs, and scrolling behavior without a terminal. `tests/smoke/tmux.sh`
repeats one check in a real TUI under tmux.

JUJUTSU (JJ)                                                  *diffbandit-jj*

In a jj workspace (colocated or not), the Git commands, the launcher, and the
commit panel use the jj backend automatically. `vcs.prefer = "git"` forces Git
in a colocated repository. Revisions accept jj revsets.

The jj "squash workflow" maps onto staging:

  unstaged view (default)   @-  -> @   (what `jj diff` shows)
  staged view (--cached)    @-- -> @-
  all view                  @-- -> @   (with stage indicators)
  stage hunk/file           moves it from @ into the staging change @-
                            (@ keeps its content)
  unstage hunk/file         moves it from @- back into @
  discard                   restores the file in @ from @-
  commit (:w)               describes the staging change and opens a fresh
                            one under @; with nothing staged, all of @ is
                            committed; without a staging change, `jj commit`
  amend                     stages into and re-describes the commit @-
  conflicts                 `jj resolve --list` entries open the merge
                            resolver; :w writes the working copy
  checkout                  `jj new <rev>`

The staging change is an undescribed, mutable @-. When @- is a described
commit, the first stage from the unstaged view creates an empty staging
change under @ (`jj new --insert-before @`), so an existing commit is never
changed by accident. Amend changes that commit instead: it abandons an empty
staging change left by the last commit, stages straight into @-, and :w
rewrites its description. `jj.default_mode = "all"` opens the all view.

Merge and diff editor for `jj resolve`, `jj split`, `jj squash -i`:
>toml
  [merge-tools.diffbandit]
  program = "diffbandit"
  merge-args = ["merge", "$base", "$left", "$right", "$output", "--path", "$path"]
  edit-args = ["edit", "$left", "$right"]
  diff-args = ["diff", "$left", "$right"]
  merge-tool-edits-conflict-markers = false

  [ui]
  merge-editor = "diffbandit"
  diff-editor = "diffbandit"
<
Conflicts with more than two sides, or that involve a deletion, are left to
`jj resolve`. When @ is a merge commit the review lists only its conflicts.
